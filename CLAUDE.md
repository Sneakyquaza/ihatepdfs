# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

iHatePDFs — free PDF & image tools site, FR/EN. Live at https://ihatepdfs.oryx3.fr, served from this machine.

## Commands

```bash
# Full stack (prod-like): web on 127.0.0.1:3000, api internal only
docker compose up -d --build
docker compose up -d --build web        # rebuild one service
docker compose logs -f api

# Frontend dev (needs the API on :8000)
docker build -t ilp-api api && docker run -d --rm -p 8000:8000 ilp-api
cd web && npm run dev                   # predev copies pdf.js worker into public/
cd web && npx tsc --noEmit && npx eslint .
cd web && npm run build

# Deploy a change to production (AGPL: push first, see below)
git push && ./deploy/update.sh          # git pull + compose rebuild + prune
```

## Tests

API tests (stdlib `unittest` in `api/tests/`: redaction detection, PPTX text geometry, PDF→Excel typing/heuristics plus end-to-end conversions of generated PDFs, including the OCR path). The image only ships `app/`, so mount the tests:

```bash
docker compose build api && docker compose run --rm -v ./api/tests:/srv/tests api python -m unittest discover -s tests
```

End-to-end (`e2e/`): Playwright drives every tool through the real UI (French locale), checks a file gets downloaded and no error box appears. It runs inside the `mcr.microsoft.com/playwright` image because the host lacks Chromium's system libs; input files are generated by `e2e/fixtures.js`.

```bash
./e2e/run.sh                                          # against http://localhost:3000/fr
./e2e/run.sh https://ihatepdfs.oryx3.fr/fr            # against production
./e2e/run.sh http://localhost:3000/fr merge-pdf,sign-pdf  # only some tools (ids from tools.ts)
```

`./e2e/audit.sh [origin]` loads every page (FR/EN × light/dark × desktop/phone) and reports console errors, failed requests, horizontal overflow and theme loss; screenshots land in `e2e/out/audit/`. Look at them after UI changes.

New tools need a case in `e2e/run.js` (`[id, fixtures, optional setup(page)]`). Server tools count against the API's per-IP rate limit (60 / 10 min); `docker compose restart api` resets it.

## Architecture

Three services behind Apache (vhosts in `/etc/apache2/sites-available/ihatepdfs*.conf`, TLS via certbot; local copies in `deploy/*.conf` are gitignored — the server's proxy config is deliberately not published):

- `web/` — Next.js 16 App Router (Turbopack), all pages statically generated under `/[locale]/...`. `src/proxy.ts` (Next 16's name for middleware) redirects locale-less paths; its matcher must keep excluding `/api`, `/_next`, `/bg-model` and files with extensions. `/api/*` is proxied to the FastAPI service by a rewrite in `next.config.ts`; **`API_URL` is baked in at build time** (Docker build arg `http://api:8000`), so the browser is always same-origin.
- `render/` — headless Chromium (Playwright) for HTML/URL→PDF, called only by the API (`RENDER_URL`). It renders untrusted pages, so it runs in its own hardened container (read-only, no caps, own network, no access to user files). Its route handler fetches every request itself against a pre-validated public IP (rebinding-proof) and follows redirects hop by hop — never hand Chromium a 3xx from `route.fulfill`, it follows those without re-entering the handler. Chromium is launched behind a dead proxy (loopback included) so anything escaping interception fails.
- `api/` — FastAPI, single uvicorn worker (rate-limit and queue state are in-process). Heavy lifting via CLI tools/libs: Ghostscript, LibreOffice (`soffice`), ocrmypdf/Tesseract, pikepdf, PyMuPDF, pdf2docx, WeasyPrint, OpenCV `dnn_superres` (FSRCNN models in `/models`).

### Tool registry drives everything

`web/src/lib/tools.ts` (`TOOLS`) declares every tool: category, icon name, `accept`, `mode: "client" | "server"`, `endpoint`, `options` and optional `editor`. From it:
- the home grid (its `<Suspense>` fallback is the full unfiltered grid, so the static HTML lists every tool; `?cat=<category>` or `?cat=pdf` filters on the client), routes (`generateStaticParams`) and the options form (`OptionsForm`, generated from `OptionDef`s, with `showIf`) are built automatically;
- `ToolRunner` (orchestration) composes `components/runner/*` (UploadHero, FileGrid, RunPanel, ResultView) and runs `runTool()` (`lib/processors/index.ts`), which either calls a lazily-imported client processor (`processors/pdf.ts`, `processors/image.ts`) or POSTs to `/api/<endpoint>` — one request per file, except `serverInput: "pair"` (`file_a`/`file_b`, compare). Options are sent as form fields with the same keys.
- Icons must be added to the explicit map in `components/ToolIcon.tsx`.

Adding a tool = registry entry + `tools.<id>` (and any new option/value labels) in **both** `i18n/fr.ts` and `i18n/en.ts` (`en` is typed as `Dict = typeof fr`, so missing keys fail typecheck) + a processor or an endpoint.

Progress is structured (`Progress` in `processors/index.ts`: phase upload/server/model/work, optional fraction, batch step); server calls use XHR for upload progress. "Continue with…" on the result screen hands the output files to the next tool through IndexedDB (`lib/handoff.ts`: consumed on arrival, 10 min TTL, memory fallback), so it also works across the full page load of `fullPageLoad` tools. `takeHandOff()` shares one in-flight read so StrictMode's double effect can't lose the files.

Theme: colors are tokens (`bg-surface`, `bg-canvas`, `text-ink`, `text-muted`, `border-line`) defined in `globals.css` for light and `[data-theme="dark"]`; don't use `bg-white`/`black/x` in UI chrome (PDF "paper", the signature pad and the white-out tool stay white on purpose). `dark:` targets `[data-theme=dark]`, set before paint by `THEME_SCRIPT`. `<html>` lives in the `[locale]` layout, so a locale switch (or the 404 shell) re-creates it on the client without that script: `ThemeToggle` re-applies the theme in a layout effect on mount. Brand-coloured text/icons use `text-accent` (lighter in dark mode); `bg-brand` stays for filled buttons.

Editors are keyboard-operable: boxes are focusable buttons using `handleBoxKey` (arrows move, Alt+arrows resize, Delete removes).

Home-page favorites and "recently used" (`lib/prefs.ts`) live in `localStorage` only; a tool is recorded as recent after a successful run.

### Visual editors

`organize`, `sign`, `edit`, `crop` (images and PDFs — a PDF crop is drawn on page 1 and applied to all pages), `redact`, `regions` (in `components/editors/`) emit `EditorData` (`lib/editorTypes.ts`) via `onChange`; client processors receive it as `ctx.editorData`, server tools get it as a JSON form field named `editor`. `BoxDrawOverlay` (`editors/shared.tsx`) is the reusable draw/move/resize-rectangles layer. Sign/edit boxes are stored as **fractions of the page as displayed** (rotation applied, top-left origin). `placeBox()` in `processors/pdf.ts` converts them to pdf-lib coordinates for pages rotated 0/90/180/270 and uses the CropBox — reuse it for anything drawn onto pages. Edit-PDF text baseline is placed at 0.95em below each line top to match the editor's CSS `line-height: 1.2`; change both together. Standard PDF fonts are WinAnsi only: `safeText()` drops unencodable characters instead of throwing.

pdf-lib cannot decrypt: `load()` in `processors/pdf.ts` rejects encrypted PDFs (`encrypted` → UI links to unlock-pdf) instead of silently writing blank pages; `openPdf()` maps pdf.js `PasswordException` the same way.

pdf.js (`lib/pdfjs.ts`) transfers/detaches the buffer it is given — always pass a fresh copy (`openPdf` does). Its worker is served from `public/pdf.worker.min.mjs` (copied by `scripts/copy-pdf-worker.mjs`, gitignored).

### API conventions (`api/app/`)

Layering: `main.py` (HTTP endpoints, thin) → `jobs.py` (all CPU-heavy library code, module-level functions taking plain values) run through `isolate.run_job()`, which executes each job in a process forked from a forkserver that preloaded `app.jobs`, with `JOB_TIMEOUT_S` (504 `timeout`, child killed) and an `RLIMIT_AS` cap of `JOB_MEMORY_MB`. Never call PyMuPDF/pikepdf/pdf2docx/WeasyPrint/OpenCV directly from an endpoint — add a job. Every uploaded PDF goes through `save_pdf()` (runs `jobs.check_pages`: rejects encrypted, empty and > `MAX_PAGES` / `MAX_OCR_PAGES`), except repair/unlock which must accept such files. External binaries (gs, soffice, ocrmypdf, tesseract) keep using `util.run()` with its own timeout.

Every endpoint wraps its work in `handle(work)`: creates a per-request `Workspace` temp dir, enforces the global `HEAVY` semaphore and `MAX_QUEUE` (503), and cleans up on error; `send()` removes the dir after the response is streamed. Uploads go through `save_upload()` (extension allow-list, size cap). Shell tools run via `run()` (thread + timeout, stderr tail in the error). Errors are raised as `ApiError(status, code, message, **params)` (`errors.py`) → `{"detail": {"code", "message", "params"}}`; global handlers turn `pikepdf.PasswordError` into `encrypted`, broken PDFs into `invalid_pdf` and anything else into `processing_failed`. The frontend never shows API text: `post()` throws `AppError(code, params)` (`lib/errors.ts`) and the UI renders `t.errors[code]` — add a translation in both dicts for every new code. Client processors throw `AppError` too.

`ratelimit.py`: per-IP sliding window + per-IP concurrency. The client IP comes from `X-Client-IP`, which Apache **sets (overwrites)** — don't switch to `X-Forwarded-For`. Rejections drain the request body first; replying mid-upload makes the Next proxy return a 500.

Redaction (`redact.py`) must stay server-side: PyMuPDF `apply_redactions` removes the text/pixels under each area, then `doc.scrub()` + `garbage=4` drop metadata, hidden text and orphaned objects. Areas arrive as display fractions and are mapped with `page.derotation_matrix`; text/regex matches are found on the page's words joined by spaces (a match redacts every word it touches). Returns 400 when nothing matched.

PDF→PowerPoint (`pptx_convert.py`) produces editable slides: all text is redacted out of the page (images/vector art kept), the page is rendered as the slide background, and each text line is re-created as a text box (font/size/color/bold/italic) at its angle. PyMuPDF gives text bboxes/directions in *unrotated* page space; `line_frame()` maps them through `page.rotation_matrix` to a centred frame + clockwise angle. PowerPoint has one slide size (the first page's), other pages are letterboxed with a uniform scale.

PDF→Excel (`tables.py`): per page, ruled tables first, else text-aligned detection filtered by `plausible()` (so paragraphs don't become tables); unit-only columns ("€", "%") are glued back; tables continued on the next page with the same columns are merged (repeated header dropped); cells are typed by `type_cell()` with the table's decimal separator from `detect_decimal()` (identifiers with leading zeros and >15-digit runs stay text). PDFs with no text layer are OCR'd first.

### Security headers

Set in `web/next.config.ts` (not Apache): CSP, HSTS, etc. The in-browser AI needs `'wasm-unsafe-eval'` and `blob:` scripts everywhere, and `/:locale/remove-bg` alone also gets `'unsafe-eval'` (protobufjs codegen). Because client-side navigation keeps the previous page's CSP, links to such pages must do a full page load: mark the tool `fullPageLoad: true` in `tools.ts` (the grid and the "continue with" buttons honour it). Run the e2e suite after touching the CSP — failures only show up in the browser.

Legal notice / privacy texts live in `web/src/i18n/legal.ts`; keep the privacy page truthful when adding anything that contacts a third party or stores data.

### Background-removal model

`web/scripts/fetch-bg-model.mjs` (prebuild/predev) downloads the IMG.LY model + ONNX runtime for `@imgly/background-removal` into `public/bg-model/` (gitignored, ~100 MB), verifying the pinned manifest hash and every chunk's sha256; the processor sets `publicPath` to it. Bumping the npm package requires updating `VERSION` and `MANIFEST_SHA256` there.

### Docker gotchas

- API base image must stay on Debian trixie: ocrmypdf refuses Ghostscript 10.0.0–10.02.0 (bookworm) for `--skip-text`/PDF/A.
- Python deps are installed from `api/requirements.lock` with `--no-deps` (complete, exact set). Edit `requirements.txt`, then run `api/lock.sh` to regenerate the lock. The lock carries `opencv-contrib-python-headless` (needed for `dnn_superres`) instead of the `opencv-python-headless` pdf2docx asks for — that's why `--no-deps`.
- FSRCNN models are downloaded at a pinned commit and checked with `sha256sum -c` in the Dockerfile.
- Source files on this host are created with a restrictive umask: `COPY --chmod=755` (api) and `--chown=node:node` (web) are required, or the non-root containers can't read them.
